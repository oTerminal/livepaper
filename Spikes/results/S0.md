## S0: does a wallpaper extension load without Apple signing?

Run 2026-09-17, macOS 27.0 (26A428), MacBook Pro (Apple M5), one built-in display, SIP on, Gatekeeper on.
Extension: `app.livepaper.spike.extension`, ExtensionKit, `EXExtensionPointIdentifier = com.apple.wallpaper`,
sandboxed, drawing one solid colour into a remote CAContext. Signed inside-out by `scripts/sign.sh`
(extension first with its entitlements file, then the app; never `--deep`).

### Hazard: after the app is (re)installed, a launch of the host app kills the running extension

pkd asks launchd to "remove all extension instances" of the extension on **every** launch of the host app.
Usually launchd finds none to remove, even with the extension running. But the first extension instance
started after the bundle has been replaced and re-registered *is* found by a host-app launch soon after
(the first or second one; a launch in the same second as the instance's start found nothing), and is killed; WallpaperAgent logs the interruption and does not start it again.

```
13:37:22.587 launchd [system:] remove all extension instances: caller = pkd.690, extension = app.livepaper.spike.extension
13:37:22.588 launchd [system:] total of 1 extension (app.livepaper.spike.extension) instances were found to remove, of which 0 were removed instantly
13:37:22.592 WallpaperAgent [com.apple.wallpaper:extension-proxy] interruptionHandler called for app.livepaper.spike.extension
13:37:22.636 runningboardd … termination reported by launchd (2, 15, 15)
```

The whole day, recovered from the unified log (`raw/hazard-timeline.log`, summarised by
`scripts/hazard-timeline.py` into `raw/hazard-timeline-summary.txt`):

- 17 removals, each followed by WallpaperAgent's `interruptionHandler called`. Every one hit an instance
  that had been started after a fresh install or re-sign (the eight S0 variants, S0c's rebuilds, and every
  later install), by the first or second host-app launch after that instance started, once per install.
- 155 host-app launches where nothing was removed. At least 112 of them happened while an extension was
  running (13:38 to 14:19: 60 launches, same pid throughout; 14:21 to 14:46: 20; 14:47 to 14:49: 12;
  14:49 to 14:51: 4; 14:51 to 14:56: 16). In each of those stretches the running instance had been started
  by restarting WallpaperAgent *after* the kill, with no re-registration in between.
- After a kill nothing restarts the extension. In the 14:19 case it was still not running 77 s later, when
  WallpaperAgent was restarted by hand (`extension started` at 14:21:03 in the summary); what the desktop
  shows meanwhile was not observed. `killall WallpaperAgent` brought the extension back every time.

So it looks like pkd retiring the instances of a plug-in that was updated, once, which is reasonable, plus an
agent that does not reconnect, which is the problem. An app update is this sequence (Sparkle replaces the
bundle and relaunches the app). The product has to expect it: after launch the app waits for the extension's
heartbeat and, when there is none, gets the agent to reconnect (restarting it if need be).
`scripts/install.sh` does the same dance so that spike runs start from a stable state.

Regenerate the log with:

```sh
/usr/bin/log show --start "2026-09-17 13:20:00" --style compact --info --debug --predicate '(process == "launchd" AND eventMessage CONTAINS "app.livepaper.spike.extension" AND eventMessage CONTAINS "instances were found") OR (process == "WallpaperAgent" AND eventMessage CONTAINS "app.livepaper.spike.extension" AND eventMessage CONTAINS "nterruptionHandler called") OR (subsystem == "app.livepaper.spike" AND (eventMessage CONTAINS "extension: INIT" OR eventMessage CONTAINS "login: status"))'
```
