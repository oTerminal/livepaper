## S8: selecting Livepaper, and restoring the previous wallpaper

Run 2026-09-17, macOS 27.0 (26A428), one display, three Spaces. Run before the S0b result was known; void if
gate G1 fires. Nothing here was seen with eyes: every answer is from API return values, the extension's log
(`raw/s8.log`) and the store file. The
previous wallpaper on this Mac was an Aerial. `Livepaper s8 …` calls `NSWorkspace` from the host app,
launched through LaunchServices; the wallpaper store is
`~/Library/Application Support/com.apple.wallpaper/Store/Index.plist`.

### What public API can do

| Question | Answer | Evidence |
|---|---|---|
| Select the Livepaper wallpaper | **No.** `NSWorkspace.setDesktopImageURL(_:for:options:)` takes an image file; nothing public names a wallpaper extension or a choice | No API. The nearest public thing is opening the pane: `x-apple.systempreferences:com.apple.Wallpaper-Settings.extension`, then one click by the user |
| Tell that Livepaper is the wallpaper | **No.** `desktopImageURL(for:)` returns `/System/Library/CoreServices/DefaultDesktop.heic` while an extension wallpaper is up | `s8: … desktopImageURL = /System/Library/CoreServices/DefaultDesktop.heic` with Livepaper selected |
| Know the previous wallpaper when it is an image (still, or a dynamic `.heic`) | **Yes**: `desktopImageURL(for:)` returns its path | After setting `Solid Colors/Cyan.png` and `iMac Blue.heic`, the call returned those paths |
| Know the previous wallpaper when it is an Aerial | **No**: the same placeholder as above | With the Aerial restored: `desktopImageURL = …/DefaultDesktop.heic` |
| Stop showing Livepaper and put an image back | **Yes, for the Space that is active on each display, and only that one** | `setDesktopImageURL` returned without error, read back, and 5 s later WallpaperAgent invalidated the extension's surfaces: `INVALIDATE surface 844ABFB1-…`. In the store (`raw/s8-store-diff-after-public-still.txt`) only two entries changed provider (`app.livepaper.spike.extension` → `com.apple.wallpaper.choice.image`), both under one Space; `Displays.<uuid>.Desktop` still named Livepaper. Reading that as "the active Space only" is an inference from the store, with one display; switching Spaces afterwards was not tried |
| Put an Aerial (or any extension-provided wallpaper) back | **No** | Nothing public names one |

### What works, but is not public API

Replacing the store file with a copy taken earlier and restarting WallpaperAgent restored what that copy
described within seconds, in the two cases tried (back to Livepaper, back to the Aerial), judged by the store's
provider and by which extension the agent launched:

```
cp Index.plist.livepaper-selected …/Store/Index.plist; killall WallpaperAgent
  -> provider app.livepaper.spike.extension, extension relaunched, ACQUIRE, "now on b-1080p30-h264.mp4"
cp Index.plist.<pre-spike> …/Store/Index.plist; killall WallpaperAgent
  -> provider com.apple.wallpaper.choice.aerials; WallpaperAgent: makeWallpaper for '[extension] com.apple.wallpaper.extension.aerials'; our extension not launched
```

The file is an undocumented property list in the user's Library; no TCC prompt, no private framework. Its
format can change with any macOS update, and writing a whole file back discards anything the user changed
in between.
