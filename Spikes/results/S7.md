## S7: 50 switches in 10 s, then kill WallpaperAgent

Run 2026-09-17, macOS 27.0 (26A428), self-signed build in /Applications, one display. Run before the S0b
result was known; void if gate G1 fires. The eyes-on half (no black or grey on the way) is on the run sheet.

### 50 switches in 10 s: PASS (by log and by displayed pictures)

`Livepaper s7 a=a-1080p30-h264.mp4 b=b-1080p30-h264.mp4 count=50 seconds=10` rewrites the config and posts the
Darwin notification every 200 ms, alternating two clips and ending on B. Switches are in place on the hosted
layer (`LoopEngine.switchTo`): one serial queue, so the last request wins; the only asynchronous hop is the
renderer's flush, and requests that arrive during it are coalesced into one restart.

```
s7: sent 50 switches in 10.0 s; last was generation 162 -> b-1080p30-h264.mp4
s7: extension reports generation 162: PASS, ended on the last request
14:50:39.073 s4: after check request: surface DBB685F7-… display 1 on b-1080p30-h264.mp4 showed 61 new pictures in 2 s: PASS
```

All 50 notifications reached the extension (50 `configChanged received` lines), no `renderer failed`, no
decoder flush requested, the extension process was the same before and after.

The other line of that check is a FAIL and is kept in the log as it came:
`… surface 3CC44A4A-… on b-1080p30-h264.mp4 showed 3 new pictures in 2 s: FAIL`. That surface is the Settings
preview (acquired with `isPreview: true`; later builds label the line). The likely reason is that a surface
that is not on screen is throttled by the window server (a covered S2 test window dropped to about one
update per second): System Settings was open but not in front at the time, which the session could not see,
so this is an assumption. In its favour: in the kill test below, run a few minutes after the accessibility
check had opened System Settings on the Wallpaper pane, the preview surface showed 60 new pictures in 2 s.

### Kill WallpaperAgent: recovers, no restart loop

`raw/s7-kill-summary.txt` (log: `raw/s7-kill.log`), on the post-review build:

```
15:29:27 killall WallpaperAgent                       (agent pid before: 42051)
15:29:47 agent pid after: 42435, extension pid after: 42438
in the 20 s after the kill: extension starts 1, acquires 2, connections accepted 1, empty connections 0
15:29:27.772 extension: INIT pid 42438 build 20260917152856
15:29:27.798 extension: ACQUIRE new surface 7295DC4B-…   (Settings preview)
15:29:27.863 extension: surface 7295DC4B-… now on b-1080p30-h264.mp4 (generation 171)
15:29:27.867 extension: ACQUIRE new surface A2805D23-…   (desktop)
15:29:27.881 extension: surface A2805D23-… now on b-1080p30-h264.mp4 (generation 171)
15:29:49.748 s4: after check request: preview surface 7295DC4B-… showed 60 new pictures in 2 s: PASS
15:29:49.748 s4: after check request: desktop surface A2805D23-… showed 60 new pictures in 2 s: PASS
```

launchd restarts the agent at once; the agent launches the extension once and acquires each surface once
(two surfaces here: the desktop, and the Settings preview because System Settings was open); the extension
reads the last config and the right clip is up within half a second of the kill. No second start, no empty
connection, so the spiral detector (4 connections in a row that never call a method → ask the app to restart
the agent, at most once per 10 minutes) had nothing to do; it has never fired. Note that in this run the
extension was not even running before the kill (the install hazard, `S0.md`), so this is also the recovery
path for that.

The first attempt at the 50-switch row "failed" because the extension had just been killed by the install
hazard (`S0.md`, "Hazard"): the app then reads a stale heartbeat. The harness now says MISMATCH rather than
FAIL for that, and `Livepaper check` shows what is really on screen.
