## S5: crossfade between two videos using two layers created up front

Run 2026-09-17, macOS 27.0 (26A428). Layer tree: `Shared/SurfaceLayers.swift`. Two
`AVSampleBufferDisplayLayer`s exist from the start. The lower one is always fully opaque once it has played;
only the upper one's opacity animates (an explicit `CABasicAnimation`, 1 s, so it runs in the render server).
New video underneath: start it, then fade the old one out above it. New video on top: start it at opacity 0,
then fade it in. Either way something opaque is always there.

### In a window: PASS after one fix

`Livepaper s5 a=… b=… count=8` crossfades back and forth; a 5 ms poll asks, at every sample, whether some video
layer is both fully opaque (presentation opacity ≥ 0.999) and `isReadyForDisplay`.

| Fade starts when | Samples | Samples with no fully visible video |
|---|---|---|
| the engine has enqueued and flushed the first frame | 4782 | 19 (about 25 ms at the start of each fade whose new video is underneath) |
| the incoming layer reports `isReadyForDisplay` | 4881 | 0 |

The first row's JSON was overwritten by the second run (`raw/s5-window.json`); its numbers are from the
session's output. The check has a blind side: when the new video fades in *on top*, the opaque lower layer
satisfies it by construction, so only the fades whose new video is underneath can fail it, and those are
where the 19 samples came from.

"Enqueued" is not "on the layer": the first compressed frame still has to be decoded. In those 25 ms the
old video had already begun to fade above a layer with no picture, so the colour underneath showed through
at a percent or two. `AVSampleBufferDisplayLayer.isReadyForDisplay` (14.4+) is the signal to wait for.

A second thing the row turned up: a layer that an earlier engine used still holds that engine's queued
frames, stamped on the old timeline. A new engine has to `flush()` the layer before it enqueues.

### In the extension

`Livepaper config mode=video video=… crossfade=1`, four times: every surface logged `now on <clip>` for each
generation, no errors. Whether it *looks* clean (no flash, no blue) needs eyes: see the run sheet.
