# Workshop items are downloaded with the user's own Steam login, through Valve's steamcmd

Decided by the product owner on 2026-09-23. It replaces the last paragraph of record 0005, which said Livepaper never downloads from Steam, and the roadmap's "No URL or Steam downloading".

Until now a Wallpaper Engine item reached Livepaper only as a folder the user already had. Wallpaper Engine runs on Windows, so on a Mac the only way to have that folder was another computer. Livepaper now gets Workshop items itself: the user signs in to Steam once inside Livepaper, browses Wallpaper Engine's Workshop, and an item goes straight into the library.

What makes this legitimate is the user's own licence. Steam lets an account download a game's Workshop items only if the account owns the game, here Wallpaper Engine (app 431960). Livepaper downloads with that account, as Wallpaper Engine would on the user's own PC, and never with any other: an anonymous login is refused for 431960 (measured below). Livepaper holds no account of its own, runs no server, and gives nobody an item their account could not download.

How it works, each part checked on this Mac on 2026-09-23:

- **Valve's steamcmd downloads the item.** The macOS steamcmd from `https://steamcdn-a.akamaihd.net/client/installer/steamcmd_osx.tar.gz`, told `@sSteamCmdForcePlatformType windows` so that it fetches what Wallpaper Engine itself would, downloaded Workshop item 3289988463 byte for byte as the Windows copy (measured), and printed `Success. Downloaded item <id> to "<folder>" (<bytes> bytes)`. It works in Steam's own folder, `~/Library/Application Support/Steam`, which the Steam app for Mac also uses: its saved login is in `config/config.vdf`, and an item lands in `steamapps/workshop/content/431960/<id>`. An anonymous login, tried in a home folder of its own, was told `ERROR! Download item 3289988463 failed (Failure).`
- **steamcmd is fetched from Valve on first use and never bundled.** Nothing found lets Livepaper redistribute it. It lives in `~/Library/Application Support/Livepaper/steamcmd/`. Valve publishes no checksum, and steamcmd replaces itself with a newer build on its first run, so a checksum of the archive would guard it for a minute. Instead the executable must carry Valve's Developer ID signature (team MXGJJ98X76, under Apple's root) before anything in the archive is put in place, and again before every run. Both the archive's steamcmd (dated 2 April 2020, Intel only) and the one it updates itself to (universal) carry it (measured). The archive is fetched over https only.
- **Rosetta.** The archive's steamcmd is Intel code, so its first run needs Rosetta on Apple silicon. Livepaper reads the executable's architectures before running it and, when Rosetta is needed and missing, says so and how to install it. The steamcmd it updates itself to has Apple silicon code and needs no Rosetta (measured).
- **Sign-in is Livepaper's own sheet**: the account name and password, then what Steam Guard asks, a code from the email or the Steam Mobile app, or an approval in the app (steamcmd prints `Waiting for confirmation...`). They reach steamcmd through a pseudo-terminal, typed at its prompts with the terminal's echo off: never as arguments, which `ps` shows to every user of the Mac, never written to disk or to the log, and held in memory for the one sign-in. Only the account name is kept (in Livepaper's defaults), because steamcmd's saved login is found by it. After that every download uses steamcmd's own saved login and never a password; a download that meets a password prompt stops and asks the user to sign in. Signing out runs steamcmd's `logout`, which revokes the saved login.
- **Browsing is Steam's own Workshop pages** (`https://steamcommunity.com/app/431960/workshop/`) in a web view in a window of Livepaper's. Browsing needs no login and no Web API key. The window stays on Steam Community over https and opens every other link in the user's browser. On an item's page a native Get button downloads that item and hands its folder to the ordinary import (`discoverSources`, then `Importer`), which treats video items, scenes and GIF scenes as it treats a dropped folder and refuses web and application items with its usual reason. The page's own "Type" tag lets Get refuse those before downloading anything. Pasting or dropping a Workshop link on the library window works the same way.
- The main app is not sandboxed (record 0002), so it can run steamcmd and write to Steam's folder. The extension is not involved.

## Considered options

- **Steam's Web API** (`ISteamRemoteStorage.GetPublishedFileDetails`, whose `file_url` serves items stored the old way). Wallpaper Engine's items come as depot content: steamcmd's content log shows item 3289988463 fetched as a manifest of depot 431960, which only a signed-in owner's client is given. A Web API key would also be one more secret to hold.
- **A reimplementation of Steam's protocol** (DepotDownloader, SteamKit2 in .NET). It works, but means shipping and maintaining someone else's client for Valve's private protocol, which Valve's own tool already speaks.
- **Third-party Workshop download sites.** They download with accounts that are not the user's, which is exactly the licence problem this record avoids.
- **Bundling steamcmd.** Simpler to start, but nothing found grants redistribution, and it replaces itself on first run anyway.
- **Keep asking the user to bring the folder** (record 0005). On a Mac it means a second computer running Wallpaper Engine.

## Consequences

- A new target, `LivepaperWorkshop` (nonisolated), holds the pure parts, each table-tested: Workshop links, steamcmd's output read into typed lines and errors, the conversation that decides what to type and when, the download list, the words, and the item page's facts. The process driver and the installer are tested against a fake steamcmd script; tests never touch Steam or a Workshop file.
- The account's password and codes never reach the log. steamcmd's own lines go to the log at debug level and private, since they name the account.
- steamcmd runs one job at a time: two would both write Steam's folder. It runs in a session of its own, and a cancel or Quit stops its whole process group.
- A downloaded item stays in Steam's folder, where steamcmd put it, as Wallpaper Engine's own downloads do; the library keeps its own copy, as it does of any source file. Getting the same item again is a duplicate before any conversion.
- Whether Steam lets a download through is Steam's decision. An account that does not own Wallpaper Engine is told `Failure`, and Livepaper says plainly that the item downloads only for an account that owns Wallpaper Engine.
