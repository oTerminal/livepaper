# M5: production engine, supervisor and render host

Turn the spike's engine into product code: the gapless loop, the layer tree of a surface, the playback supervisor, the wallpaper extension that WallpaperAgent hosts, and the app's client for it. Lane A. See `docs/roadmap.md` (Engineering decisions, Architecture) and decision records 0001 to 0004; the evidence behind them is in `Spikes/results/`.

Its inputs are settled: record 0001 (the host is the extension; gate G1 passed), 0002 (the library and the notifications), 0003 (stopping holds a still), and M2-core.md's seams, which this milestone uses and does not re-implement: `decidePlayback`, `judgeProgress`, `judgeHeartbeat`, `allowAgentRestart`, `pictureRect`, `RenderState`, `Heartbeat`, `LibraryLocation`.

## Rules

- Code goes in `LivepaperPlayback` (nonisolated), `LivepaperSystem` (MainActor), a new `WallpaperAgentBridge` target in `LivepaperKit`, and the extension target in `WallpaperExtension/`, declared in `targets/extension.yml` and included from `project.yml` as M0 planned. The App target gets only what the checks below need.
- All private API lives in `WallpaperAgentBridge`: every `dlopen`, class name, selector and ivar write, the request-field extraction, and the one private selector on the video layers. The extension links it; nothing else does. It starts with a self-check that logs one line naming whatever is missing, and the heartbeat carries the result (`selfCheckFailed`).
- The extension reads the library and nothing else (record 0002). Every path it opens comes from a `LibraryPath` through `LibraryLocation`; the home folder comes from `getpwuid`, in one place. It writes no file: the heartbeat is all it says.
- Nothing blocks on the cooperative pool (M4-import.md, "As built"). `LoopEngine` is an actor whose executor is its own `DispatchSerialQueue`; the readers' blocking calls run there and nowhere else. The XPC handler hops to the main actor and returns.
- Nothing polls while nothing changes. The displayed-picture counter runs for the seconds a check needs (after a wake, after a recovery, when asked) and stops. The heartbeat is one timer.
- Vocabulary is `CONTEXT.md`'s: surface, display, render host, poster, loop seam. A type called `Screen`, `Monitor`, `Renderer` or `Thumbnail` is a review failure.
- Anything adapted from Phosphene (MIT) keeps its attribution in a `NOTICE` at the repository root, as `Spikes/NOTICE` does. No GPL project is read.
- Test-first at the seams below. What touches AVFoundation or the agent is proved by the checks table, on screen, with the log kept.
- The extension's bundle identifier is what the wallpaper store keys the user's selection by, and the choice identifier `livepaper` is the configuration it carries (records 0001 and 0003; M7-system-integration.md writes it). Both are chosen here, once, and never change.

## What the spike settled

- **The loop** (`Spikes/results/S2.md`). Two `AVAssetReader`s on the video track, `AVAssetReaderTrackOutput` with no output settings, compressed samples straight into the layer's `AVSampleBufferVideoRenderer`, a second reader opened ahead, one ever-increasing timeline. A frame is a buffer with at least one sample and a data buffer; the reader's marker buffers are left out. Every sample is stamped with its output (edit-list-adjusted) time plus the pass's offset; the next pass starts at `end of last frame − PTS of first frame`; `ResetDecoderBeforeDecoding` is stripped from every pass after the first. The first frame goes in with the clock stopped and `DisplayImmediately`. A renderer that fails or asks for a flush restarts from a fresh reader, because the reader is mid-GOP. A layer inherited from an earlier engine is flushed first. 200 loops with no presented gap over 1.5 frame durations, in a window and in the extension.
- **Progress is displayed pictures**: `displayedPixelBuffer()`, told apart by the `IOSurface` ID behind it, polled. Not the timebase and not `AVVideoPerformanceMetrics`; neither saw the seam defect.
- **Switching in place** (S7): one serial queue, the last request wins, requests that arrive during the renderer's flush coalesce into one restart. 50 switches in 10 s ended on the last.
- **Crossfade** (S5): two video layers made up front, the lower one opaque once it has played, only the upper one's opacity animated, by an explicit `CABasicAnimation` so that it runs in the render server. The fade starts when the incoming layer reports `isReadyForDisplay`, not when its first frame is enqueued: 4,881 of 4,881 samples then had a fully visible video.
- **Surfaces** (S3). The agent hands the extension one surface per display, not per Space; the lock screen is the same surface with `presentationMode = locked`; the Settings preview is a second surface for that display, flagged `isPreview`, alive while Settings is open. So the roadmap's "one decode per display, fanned out" is one engine per surface, and the preview is the one time a display costs two. A replug is a new surface ID for the same display UUID; the old surface never returns, so what a returning display shows comes from the UUID, and the 15 s teardown grace only covers the agent's routine reconnects. A monitor the Mac has never seen was not tried.
- **Covered means not composited** (S3). Under a fullscreen app a display's surface shows no new pictures while the engine feeds it. The watchdog must not call that a stall, and it is a first-hand signal that the display is covered.
- **A mode change is stretched, not renegotiated** (S3). The agent sends nothing and scales the old surface into the new size, each axis on its own. The extension has to notice the reconfiguration itself and re-lay; whether the agent then stretches the corrected layer again is for this milestone to find out.
- **The install hazard** (`S0.md`): after the bundle is replaced, the next host-app launch kills the running extension once and the agent does not start it again. `judgeHeartbeat` and a rate-limited agent restart are the cure. Killing the agent is survivable (S7): it comes back, launches the extension once, acquires each surface once.
- **Snapshots** (S6, by construction only): the agent asks the extension for a snapshot and shows it while no live context is hosted. Handing back the picture on screen, cropped as the layer shows it, is what should keep a lock transition from going grey. Nobody has watched it yet.
- **With no app running** (record 0003) the extension reads the last render state itself, holds each display's poster when the state is stopped, keeps what it shows when the state cannot be read, and shows a neutral colour when there is none.
- **The heartbeat's `desktopSurfaceAcquired` flag** is how the app learns that Livepaper is selected (S8b). Selecting it is M7-system-integration.md's.

## Parts

| Part | Module | Does |
|---|---|---|
| `LoopEngine` | `LivepaperPlayback` | One engine on one `AVSampleBufferDisplayLayer`: `play(_ url:)`, `switch(to:)`, `pause()` and `resume()` with a rate ramp (content, exempt from the interface rules, `docs/design/skill-mapping.md`), `suspend()` (readers and decoder released, the last picture kept where the renderer allows), `stop()`, `displayedPictures(over:)` for the watchdog. A volume above zero reads the audio track through the same reader into an `AVSampleBufferAudioRenderer` on the layer's synchroniser; at zero, the default, the audio track is not opened |
| `SurfaceLayers` | `LivepaperPlayback` | The layer tree of one surface, built before the first reply: a still layer for the poster and two video layers, all laid out by `pictureRect` from the display's pixel size, the wallpaper's size and its `Presentation`, so that the still and the video line up and Fit's bars are black. `show(_:crossfade:)`, `holdStill(poster:)`, `showNothing()`, `layout(surface:)` |
| `PlaybackSupervisor` | `LivepaperPlayback` | Takes the current `RenderState`, the live surfaces by display and a clock. For each display: `decidePlayback` on `playbackConditions(for:now:)`, again when a new state lands, again 1 s after a wake (`docs/roadmap.md`, Risks) and when the state's conditions expire; `.play`, `.pause` and `.suspend` mapped onto the engine; a stopped state holds the poster. After a wake, an unlock, a recovery or the agent's `update`, the watchdog: count displayed pictures on the surfaces that are on screen and not covered, `judgeProgress`, climb `.flush` → `.rebuildSurface` → `.rebuildPipeline` inside the process, and ask the app for `.restartAgent` through a heartbeat flag |
| `PreviewPlayer` | `LivepaperPlayback`, the one `@MainActor` type in that nonisolated module | An `NSView` with one engine, one layer and a `Presentation`, for the inspector and for the tile's live preview (M6-screens.md hands it to `WallpaperTile`). Plays an optimised copy or a hover preview; releases its decoder when hidden or removed |
| `WallpaperAgentBridge` | `LivepaperKit`, new target; its ObjC declarations in a C target it depends on, since a package has no bridging header | `load()` self-check; the remote-context and snapshot replies; the settings view models (one group, one item, "Livepaper", `livepaper`); the per-selector class whitelist; request field extraction; `disallowDisplayCompositing` for the video layers |
| Extension | `WallpaperExtension/` | The `AppExtension` entry; the XPC handler; a surface store keyed by surface ID that knows each surface's display UUID and whether it is the preview, reuses a context re-acquired within 15 s and tears an abandoned one down after; the render-state reader with its fallbacks and the Darwin observer; the heartbeat; the spiral detector; a `recover` observer; the display reconfiguration observer; the supervisor. Entitlements: the sandbox and the read-only exception for `/Library/Application Support/Livepaper/`. Ad-hoc signed by Xcode locally and in CI, as the app is |
| `ExtensionHostClient: RenderHost` | `LivepaperSystem` | `activate()` records the launch time, starts listening and reports `.connecting`. `apply` replaces `render-state.json` atomically and posts the notification. `status` from the heartbeat and `judgeHeartbeat` on a clock: `.live` or `.notSelected` by the desktop flag, `.unavailable` on `selfCheckFailed`, `.recovering(level)` while the extension stays silent, `.stopped` after `deactivate`. `recover(.restartAgent)`, whether from the ladder, the spiral flag, the watchdog's request or the status line's button, goes through `allowAgentRestart` and then restarts WallpaperAgent with one signal and a wait, never a burst (`docs/research/wallper.md`); the lower levels are posted to the extension as a notification whose state is the level. `deactivate` writes the stopped state |
| Sensors | `LivepaperSystem` | `AsyncStream`s, with a fake for each in `LivepaperTestSupport`: connected displays (UUID, pixel size, frame; reconfiguration debounced), power (Low Power Mode, battery), lock, sleep and wake, per-display sleep, covered displays. A folder turns them into `SensedConditions` and applies a new state when they change, and again at half of `PlaybackConditions.expiry` while any condition would pause a display, so that a live app never lets its conditions go stale and a dead one frees the wallpaper |
| Developer menu | `App/` | Until M6-screens.md replaces the placeholder: set a wallpaper from the library on one display or all, pause all, resume, restart the wallpaper service, the host's status, and "Log playback metrics", which switches the displayed-picture probe on for the session and has the extension log, every 20 loops and per surface, what the spike's `summary` logged. Off by default, never on in ordinary use. The other items go when the screens land; "Log playback metrics" stays, because M8-hardening.md's soak and M10-1.0.md's checklist turn it on |

Occlusion is sensed from the window list's bounds, level and owner, never window names (those need Screen Recording, and the roadmap rules out permission-gated API): a display is covered when one on-screen window at normal level or above, not the app's own, contains the display's frame. Several windows that together cover a display count as not covering it; that is v1's known gap.

## Seams for test-first work

Tests (Swift Testing) run under `swift test` with an injected clock and no display, so they cover the logic around AVFoundation and the agent, not AVFoundation or the agent.

| Seam | Tested as |
|---|---|
| Pass ledger | Pure: from each frame's media PTS, output PTS, DTS and duration, the retimed stamps and the next pass's offset. Rows from `S2.md`: a first frame at media time 0.0667 with an edit list to 0; B-frames arriving out of order (`enqueuedUntil` is the maximum, not the last); a marker at the track's duration is not a frame; the seam step is one frame duration |
| Switch coalescing | Reducer over request, flush began, flush ended: the last request wins; requests during a flush become one restart; a request for the URL already playing is a no-op |
| Crossfade plan | Pure: from which layer is in front, which layer starts, which fades and in which direction, so that something opaque is always there; nothing showing yet starts on the lower layer without a fade; a request while the first engine is still starting redirects it |
| Displayed-picture counter | Given a sequence of surface IDs with times: the same ID does not count, a change does, and the count over a window is what `judgeProgress` gets |
| Playback mapping | Table: `PlaybackDecision` × engine state → engine calls; `.pause` keeps the readers and `.suspend` releases them; a stopped state holds the poster; conditions that expire are decided again at expiry |
| Watchdog scheduling | Reducer: which events start a check (wake, unlock, recovery, the agent's `update`), which surfaces it may judge (on screen, not covered, not the preview), the ladder by attempt, `.restartAgent` becoming a heartbeat flag |
| Surface store | Reducer with a clock: acquire, invalidate, a re-acquire within 15 s reuses the context, teardown after; a new surface ID for a known display UUID gets that display's assignment; the preview flag; a display absent from the state shows nothing |
| Render-state reader | Table: missing → none; unreadable or an unknown major version → keep what is shown; stopped → the still; readable → apply. Uses M2-core.md's `render-state-v1.0.json` |
| Spiral detector | Four empty connections in a row signal; a served connection resets the count; at most once per 10 minutes, on the clock |
| Request field extraction | Against fake payload objects shaped like the private classes: destination size, scale and display ID, `isPreview`, the surface UUID, the presentation mode |
| Host status | Reducer over heartbeat, silence and the clock: `.connecting` → `.live` / `.notSelected` / `.unavailable`; silence → `.recovering(level)` by `judgeHeartbeat`; a restart only when `allowAgentRestart` says so |
| Covered displays | Pure `coveredDisplays(windows:displays:) -> Set<DisplayIdentity>`: a fullscreen app, a maximised window, a window on another display, the app's own window, a window below the desktop level, two windows that tile |
| Conditions folder | Reducer over sensor events and ticks: one `SensedConditions` per change, a refresh at half the expiry only while a rule would pause something, none otherwise |
| `Heartbeat.Flags` | Core gains `restartAgentRequested`; a row in its round-trip table |

Each row's log excerpt goes into the PR; the crossfade and the lock transition go in as video, the still and Fit's bars as screenshots (CLAUDE.md). `Tools/pr-media` takes an app's window at the normal level; the desktop's wallpaper window belongs to WindowManager at the desktop level, so `shot.sh` and `record.sh` need a way to take that one (the spike's `wallpaper-snap.py` finds it, and needs Screen Recording: that is allowed for capture tooling on the developer's Mac, never for product code).

## Done when

- The seam tests pass with `swift test --package-path Packages/LivepaperKit`, locally and in CI, and `make gen build test lint` is green with the extension target built.
- Every row of the checks table passes, with its evidence in the PR.
- `PreviewPlayer` plays an optimised copy and a hover preview in a plain window, honours `Presentation`, and releases its decoder when hidden: the inspector preview reuses the engine.
- `HeartbeatTiming.standard` is measured against the product extension and no longer marked provisional; the heartbeat interval is shorter than its lifetime.
- `NOTICE` at the root carries the Phosphene attribution for what was adapted.
- An "As built" section here, as M4-import.md's, for M6-screens.md and M7-system-integration.md to build on: the preview's API, the notification names, the bundle identifier, what the mode change needed, and what audio did at the seam. It also records the extension's subsystem and the exact wording of every log line another milestone reads: the bridge self-check line, the surface events with their wallpaper and generation, the watchdog verdicts and ladder steps, and the metrics line. M8-hardening.md's parser pins those rows and M10-1.0.md's checklist quotes them, so a rename here fails a test rather than counting zero.
