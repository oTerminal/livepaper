# M10: 1.0

Ship 1.0 and leave behind the checklist every macOS beta seed runs through, since the render host is private API with no fallback (`docs/roadmap.md`, Risks; records 0001, 0003, 0004). Nothing is built here.

## Rules

- A maintainer runs the checklist on a Mac with the seed installed, against the release build, never `Spikes/`. CI (macos-26, no beta image) cannot.
- Rows run in order; the run stops at the first failure.
- Every run goes in `docs/seeds.md`, newest first: macOS build, date, app version, then this table with a result and log line per row.
- Vocabulary is `CONTEXT.md`'s.

## Beta-seed checklist

A row takes minutes at most. Logs: `log show --last 5m` on the extension's subsystem; metrics: "Log playback metrics", the one Developer-menu item M6-screens.md keeps (M5-engine.md).

| Check | How | Pass when |
|---|---|---|
| 1. Discovered | `pluginkit -m -v -p com.apple.wallpaper \| grep -i livepaper` | One line names the extension |
| 2. Bridge self-check | Open System Settings > Wallpaper, which launches the extension | The self-check line M5-engine.md's "As built" records, as the spike's `bridge: WallpaperExtensionKit loaded, all 15 payload classes present`, and no `MISSING classes` line (`Spikes/results/S0.md`) |
| 3. Ivar offsets | Same log, after `ACQUIRE` | No `layout unexpected` line for either payload class, in M5-engine.md's wording (`Spikes/Extension/PrivateBridge.swift`; both fail closed) |
| 4. App self-check | Launch the app; read the status line | `RenderHostStatus` `.live`, not `.unavailable` (`selfCheckFailed` clear); no warning in `StatusLine` |
| 5. Settings entry | System Settings > Wallpaper | "Livepaper" listed; its preview plays the display's wallpaper (M5-engine.md) |
| 6. Sandbox exception | Set a wallpaper; `log show` on the extension's subsystem and on `sandboxd` | Plays from `~/Library/Application Support/Livepaper/`; no `deny(`, no tccd prompt (record 0002, `Spikes/results/S1.md`) |
| 7. Store deselect, select | Settings > "Stop using Livepaper as wallpaper"; then select again as onboarding does | Previous wallpaper back within 5 s; select restarts the agent once, `desktopSurfaceAcquired` within 1 s (`Spikes/results/S8.md`); no fallback to the pane (record 0003) |
| 8. Surfaces and lock | Two displays, different wallpapers; lock | Each plays its own; video on both lock screens; `presentationMode=locked` logged (`Spikes/results/S3.md`) |
| 9. Snapshot | Lock and unlock, watching | No grey frame either way (M5-engine.md, S6) |
| 10. Loop | Metrics on; 20 loops of a 5 s 30 fps optimised copy | No presented gap over 1.5 frame durations at any seam (`Spikes/results/S2.md`) |
| 11. Sleep and wake | One lid cycle | Pictures advancing within 2 s on every display, the watchdog `.healthy` (`Spikes/results/S4.md`) |
| 12. Hot-plug | Cable out 6 s, then 90 s | Back on its own wallpaper within 2 s of `ACQUIRE`, same UUID (`Spikes/results/S3.md`) |
| 13. Login item | Toggle it; log out and in | The app launches; Login Items lists it once; the toggle matches `SMAppService` (`Spikes/results/S0c.md`) |
| 14. Gatekeeper | Download the current DMG with Safari; open from /Applications | Runs, extension included, after Open Anyway alone, no `xattr` (`Spikes/results/S0b.md`) |
| 15. Sparkle | Update from the previous release | Login item, extension and assignments kept (M9-release-engineering.md); desktop live again without a click (M5-engine.md, Hazard) |
| 16. DMG | Run M9-release-engineering.md's packaging script | The image command that milestone's "As built" records writes an image that mounts and verifies (record 0004) |
| 17. Scene | Set a scene on the desktop; lock; unlock | `loaded … drawn by WallpaperEngineScene` and `shows … in the Metal slot` (M11-wallpaper-engine-scenes.md, "As built"); the scene moves on the desktop and the lock screen; the watchdog `.healthy` (record 0007, `Spikes/results/S10.md`) |

## When a row fails

- The user sees what the risks row promises: the poster still on each display and the status line saying so. Unobserved: the desktop when the extension cannot answer the agent; the run records it.
- The maintainer files the run, then ships a fix through Sparkle when the cause is in the bridge or the store code, or a README note naming the seed and the row. Row 7 failing costs one click in System Settings (record 0003), not a release.
- A window render host is not built for it (roadmap, record 0001).

## Done when

- `docs/seeds.md` holds a passing run on the candidate on current macOS 26 and 27.
- The criteria table is met; `v1.0.0` tagged, its release published.
- The README has Known gaps, "Tested on" and Open Anyway.
- `make gen build test lint` is green.

## Out of scope

New features. A window render host, notarization, HDR. The checklist in CI. The next macOS's seeds, after 1.0.
